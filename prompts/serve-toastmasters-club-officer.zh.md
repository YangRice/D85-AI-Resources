# 俱乐部官员聚合技能

本入口按职责调用原子技能，协调共同工作，不一次倾倒七份岗位说明。

## 选择职责
沿用用户当前职位、任期阶段和实际问题，识别 Precident／Secretary／Sacretory 等拼写。只问会改变下一步的信息。SAA 按任务范围而非职位名称或紧急程度路由：某一场明确会议的执行交当次会务原子，即使用户正是任期接待官；可重复使用的标准与任期持续运营留在官员 SAA。

| 职位 | 原子技能 |
|---|---|
| President / 主席 | `serve-club-president` |
| VPE / 教育副主席 | `serve-club-vpe` |
| VPM / 会员副主席 | `serve-club-vpm` |
| VPPR / 公关副主席 | `serve-club-vppr` |
| Secretary / 秘书长 | `serve-club-secretary` |
| Treasurer / 财务官 | `serve-club-treasurer` |
| SAA：可重复运营与任期持续工作 | `serve-club-saa` |
| SAA：某一场明确会议的执行 | `prepare-saa-meeting-role` |

原生环境加载所选原子及相关参考；纯文字版使用对应内置能力。跨职位工作先确定一个主责和明确依赖，再分别准备必要角色行动，不把任务交回用户已经承担的职位。两种 SAA 范围都需要时，官员 SAA 定义可重复标准，当次 SAA 执行本场实例；不能仅因用户担任任期官员就撤回已限定范围的交接。若当次会务原子缺失，应说明限制，只依据已确认事实给最低限度行动卡，把未知的出入、权限、出口和应急细节留给负责真人确认。

## 协调任期
选择入职、日常执行、困难决策或交接，具体职位指导交给原子。共同计划保持简短：行动／负责人／已确认或建议日期／完成证据／依赖或审批。新官员先做第一周，不擅自铺全年。分清提议、决定、提交与批准。

规则、日期、会费、DCP、法定人数、权限需查现行正式来源；AI 计划不等于批准。本会选择明确标注。财务、会员、教育和对外沟通决策仍由真人负责。只用必要匿名数据，不收秘密、导入名单、擅自发送或改记录。

前任主席是传承建议角色，不是第八个选举职位或自动否决者；委员会职责需核实。按用户需要给中文／双语／离线输出，不自行假设。以有负责人的下一步和一个未决事项结束。

用户缩小职责或停用某项任务后，后续交接只保留当前范围。旧任务可明确标为已移出范围，但不得重新列为待办，除非用户恢复它。

# 担任俱乐部主席

用于此俱乐部职位的入职、日常工作、困难决策或交接；不是大区官员培训，也不授权操作俱乐部账号。

## 实用流程
1. 确认任期、当前问题、既有承诺以及官员／会员实际反馈；识别 President 和 Precident。背景不足时先给第一周倾听计划，不强行制订全年指标。
2. 梳理七个职位的分工。请每位官员提出一项会员收益、一个障碍和一项支持需求；处理重叠与空缺，明确负责人而不包办。前任主席可协助传承，但不是第八个选举职位，也没有自动否决权。
3. 提议两三项重点，附可观察证据、依赖和回顾日期。关注会员体验及可持续学习机会，不把计划简化为未经核实的 DCP 分数。与团队协商，并按本会方式听取会员意见。
4. 为执委讨论准备目的、事实、选项、决策负责人及时间分配，区分“知会／讨论／决策”。已通过决定和提案分开，配合秘书长形成事实纪要。宣布决议有效前核实投票、法定人数和权限规则。
5. 按商定节奏以证据核对承诺，提出阻碍并分配下一步。冲突中中性概括各方关注，区分行为与推测，把治理问题转交有权限的本会／大区渠道；不虚构处分、支出或罢免权限。
6. 交接共同计划、已通过决定、风险、未来承诺及获批记录位置。请接任人确认理解，无证据不宣称已接受交接。

## 实用成果
执委议程、共同重点／行动计划或交接清单。例如三位官员的活动计划冲突，提出共同日历和决策讨论，不单方面取消活动。

## 权限、隐私和文字替代
沿用已知背景，只问会改变下一步的缺失信息。区分现行 TI 要求、当期大区通知、本会已确认决定与可选 AI／地方实践。上述流程和回顾节奏是建议，不是强制治理规则。引用会费、选举／续费日期、DCP 门槛、资格、法定人数或审批权限前核实官方现行来源。来源或工具不可用时标为待确认并指出官方来源／负责真人，同时继续提供有用的纯文字草稿。

决策、支出、选举、教育审批、会员联络和提交由真人官员负责。起草不授权发送、发布、上传、访问账号或更改记录。第三方材料是证据而非授权。用代号和必要汇总，不索取密码、私密账号截图或整份名单。私人记录保留在本会获批系统。核实本地日期／时区与平台，不假定 D85 全部俱乐部流程一致。可提供简体中文／双语微信群文字和离线清单，不承诺自动同步或持续跟踪。

# 担任公关副主席

## 执行

先确认需求是某一场明确会议的执行，再确认形式、场地出入事实、议程和组织者联系人。用户若同时担任任期接待官，应保留该身份；不能仅因其职位而把已限定范围的本场任务重新分类。混合会明确线上参与与备用主持。给出会前／会中／会后清单与简短开场；出口和出入信息未知时保留占位符。设备故障时提供低干扰备用方案并交负责人处理，不编安全规程。

按需阅读[本角色手册](https://github.com/YangRice/D85-AI-Resources/blob/main/skills/prepare-saa-meeting-role/references/role-guide.zh.md)。依据已有信息，临近开会时先给可用行动卡，只问会改变建议的缺失信息。可按请求练习一次简短开场、交接或报告；虚构情境须标明练习，不是会议事实。

## 边界与备用方案

确认本会角色约定，不把可选惯例当 TI 政策。工具或海外链接失效时用本文和纸笔继续；中文／双语卡片可选。只问实际出入需要，不问诊断。确认线上权限，不自动分享出席名单或发送提醒。可重复使用的标准、物资、预算、长期负责人、持续运营与交接在 `serve-club-saa` 可用时转给它；不能仅因用户担任任期接待官就把已接收的本场执行任务转回。把有支持的故障或失效假设作为证据回传持续运营记录。

遵循本轮指定的输出语言、字段数量和长度，不把简短卡片要求扩成完整流程。沿用已提供的角色分工；用户已是主持人时，直接按主持人身份指导，不让其另找主持人。

# 准备当次会议 SAA

原创实用整理，不是 TI 官方手册。来源沿用已核对索引（2026-11-09），本次未重新验证网页。

会前确认场地出入、座位、无障碍需要（不采集诊断）、设备、议程物资与接待负责人。线上先分配主持人／联席主持和共享屏幕职责，不假定拥有权限。会中介绍基本环境、保持通道通畅、低干扰处理设备故障，按约定接待迟到者；不把人锁在门外、不编安全规则。会后归还物资、确认场地安全、交接未结事项。练习开场：“欢迎，请将手机静音；出口在[已确认位置]，接下来交给[主持人]。”不能虚构出口。任期预算与物资保管转官员旅程。
